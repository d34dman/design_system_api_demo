Drupal · Design System API · v0 demo

One module, one stylesheet, every theme

The Media Library, styled once against the design contract, looks native in Default Admin and Claro and plain but deliberate in Olivero and in Stark, a theme with no CSS. It follows dark mode, RTL, high contrast and forced colors, and an author rebrands it in one file without touching code.

Every screenshot on this page is captured by tests/proof/capture.mjs from the demo site (Drupal 12.0.0-beta1), with an axe-core scan of each cell. Rebuild it with one command; nothing here is mocked.

The seven moments

  1. BeforePilot off. Each admin theme ships its own Media Library CSS; Olivero and Stark get almost none.
  2. One module, every admin themePilot on. The themes' Media Library CSS is switched off; adapters map the contract to each theme's variables.
  3. Same module, frontendOlivero and Stark get the contract's plain defaults.
  4. ModesDark (from the OS, or chosen on the page with data-ds-mode, also together with more contrast), RTL, prefers-contrast and forced colors, from one stylesheet.
  5. The author fillsA registry file rebrands the card border on Olivero only, with provenance.
  6. The guard railThe linter passes the pilot and fails a literal color, by rule ID.
  7. ReceiptsNo hex values, no theme names, a quarter of the CSS.

Moment 5

The author fills: one registry file

ddev ds-brand on drops this file into the registry. Two values change: the shared color.border.primary and the media card's own border. Everything else, and every other theme, is untouched.

design-system/registry/olivero.registry.yml 

      

      

        drush ds:resolve media-card.border --theme=olivero
        

        … --mode=dark
        

        … --theme=default_admin (no author file: the adapter fills it)

The rules are data in the module (design_system_api.rules.yml); the stylelint rules carry the same IDs. The component's tokens each suggest a mapping to the shared vocabulary, so a new theme needs no setup.

Run it yourself

    
git clone https://github.com/d34dman/design_system_api_demo.git
cd design_system_api_demo
ddev start && ddev install-demo
ddev admin-theme claro          # or default_admin
ddev frontend-theme stark       # or olivero
ddev ds-brand on                # moment 5
ddev ds-lint                    # moments 6 and 7
cd tests/proof && npm install && npm run capture && npm run gallery

    
Until the module's 1.0.x branch and the demo are published, this runs in the workspace (ddev workspace-mode on).
